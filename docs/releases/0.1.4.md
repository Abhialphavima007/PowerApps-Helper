# PowerApps Helper 0.1.4

Prepared locally on 20 November 2026. GitHub publication is performed by the existing release workflow when the owner pushes to `main`.

## Changes

- Redesigned deployment History with working detail views and CSV/JSON downloads.
- Organized solution exports and deployment notes under `Base folder / Client / Source to Target / Solution`, with distinct export filenames. OneDrive creates the required folders; storage failures are reported, including agent repair re-exports.
- Collapsed sidebar icons expand on hover or keyboard focus, resize the main content, and collapse when the pointer/focus leaves.
- Persistent Light/Dark switching in the sidebar and Settings, with save-failure rollback and retained deployment drafts.
- Shared glass styling and identical layout geometry across Light and Dark, with responsive wrapping and accessibility preference fallbacks.
- Client name defaults to the active tenant, using a silent tenant-name lookup with local fallback. Names remain editable and tenant-specific; clearing a manual name restores the automatic value.

Affected areas: renderer layout, History/Deploy/Settings views, settings persistence and IPC, optional tenant-name authentication, export storage, and deployment storage warnings. Application and lockfile versions move from 0.1.3 to 0.1.4; dependency resolution is unchanged.

## Local build

Commands verified from the repository manifest/workflow:

```powershell
npm run build:renderer
npx --no-install electron-builder --win nsis --x64 --publish never --config.directories.output=release/v0.1.4
```

The renderer build passed. The initial Windows packaging attempt failed while extracting macOS symlinks in the `winCodeSign` tool archive because this Windows session lacks the required privilege. A retry also encountered a locked output file and a failed NSIS resource-cache rename. Local recovery extracted the Windows tools from the downloaded archive into an ignored workspace cache and copied the successfully extracted NSIS resources into their expected cache directory. Executable version stamping remains enabled.

The final successful installer command used the inspected, version-stamped packaged app from the retry:

```powershell
$env:ELECTRON_BUILDER_CACHE = Join-Path (Get-Location) 'release/v0.1.4-builder-cache'
npx --no-install electron-builder --win nsis --x64 --publish never --prepackaged release/v0.1.4-ready/win-unpacked --config.directories.output=release/v0.1.4-final
```

The cache override was scoped to the build process and restored afterward. This local cache recovery does not change the GitHub workflow or repository build settings. The normal command above remains the standard build route on a host with working tool extraction.

Built with Node 22.18.0, npm 10.9.3, Vite 5.4.21, electron-builder 24.13.3, and Electron 31.7.7 using installed dependencies. `npm ci` was not rerun locally; the GitHub workflow installs from the lockfile with Node 20.

## Configuration and recovery

No new dependency, app registration, or required configuration is introduced. Existing theme/client-name preferences and export settings are retained. Tenant naming falls back when silent Azure Resource Manager access is unavailable. Folder organization applies to future exports; existing exports/history are not relocated.

Before distributing an upgrade, retain the previous installer and a private backup of the application's existing user-data directory while the app is closed. If the upgrade fails, close the app and reinstall the retained version; restore the backup if settings recovery is needed. This recovery procedure and installer upgrade path have not been exercised for this candidate. Do not include user-data backups or credentials in the repository or release assets.
