# PowerApps Helper 0.1.5

Release candidate prepared on 26 November 2026. Windows x64 is the local target. Public GitHub publication remains pending the required independent/security reviews and release checks (REL-01). No exception is self-approved (STD-02).

## Included changes

- Teams settings redesign, encrypted workflow-address persistence and workflow checks that do not open Graph consent. The optional direct **Send as me** connection still follows Microsoft consent rules.
- Deployment updates to selected people, an existing group chat and a Teams channel, with saved event choices and progress intervals. Messages include solution/version, export type, source/target, current stage and run details.
- Optional local Codex MCP deployment-update support. Codex supplies observed updates; it does not independently monitor deployments just by being enabled.
- Paginated History with bounded rows sent to the renderer, filtering and on-demand details. The local JSON history is still read/sorted in full per query.
- Success/failure outcome reporting to the captured deployment target, with an optional central environment for approval evidence and profiles.
- Dependency approval with source/target details, friendly component names/types and the import error below. Exact approval evidence gates source additions, publication, re-export and bounded retries.
- Approved dependency repairs use the existing source Dataverse API sign-in. The separate desktop Helper Dataverse MCP setup is no longer required; saved settings migrate without changing their destinations.
- Automatic idle-sleep protection covers manual export/import and the complete agent run, including approval waits. It releases after the last overlapping operation finishes or fails.
- Generic installation/profile guidance and compatibility with **PowerAppsHelper solution 1.1.3.0**, whose profile form offers an account picker instead of manual trusted-user GUID lookup.

Both package version files move from 0.1.4 to 0.1.5. Dependency declarations/resolution, app ID, publisher prefixes and saved-settings contracts are retained. The installer packages the entire current desktop implementation, including earlier 0.1.4 functionality.

## Configuration

Close the running Helper app before updating, then restart it. Existing settings and credentials are retained by the unchanged application identity; installer upgrade/recovery still require host verification. Keep a private backup of existing app data while the app is closed and retain the previous installer. Do not distribute that backup.

For new installations, follow [local-handover.md](../local-handover.md). Each person supplies their own Microsoft sign-in, environments and flow connections. Solution packages do not carry profiles, credentials, connection accounts, role assignments or signed webhook addresses. Select the actual Dataverse connection account used by the approval flow in **Approval flow account**; Helper fills the canonical trusted ID after validating that user.

Teams workflow delivery requires the corresponding Helper workflow and a private signed address saved in Settings. Direct **Send as me** mode can require tenant approval. Approval requests must be answered through the matching Microsoft approval request; Teams chat replies do not grant repair permission.

## Remaining checks

Fresh approval/Teams delivery, physical idle-sleep behavior, another-computer installer/upgrade, managed downstream import and recovery rehearsal remain unverified. The Windows installer is unsigned; macOS, Linux and ARM64 are not built locally for this candidate. No release certificate or new dependency is introduced.

Keep Helper running and connected until deployment completes. The sleep blocker prevents automatic idle sleep; forced sleep, lid policies, hibernation, shutdown, restart and network loss are outside this protection. The desktop is not a durable cloud worker.

The full `docs/standards.md` is absent (D01). Independent non-author approval and a second qualified reviewer for the security-sensitive approval/Teams integration are required before public publication. No reviewer, checker finding or release gate has been waived.
