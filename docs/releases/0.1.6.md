# PowerApps Helper 0.1.6

Prepared 27 November 2026 as an unsigned local Windows x64 release candidate. Public publication remains pending independent non-author and qualified security review. This preparation does not push or tag the repository.

## Changes

- Solution import monitoring now allows **60 minutes per normal import** and **180 minutes for a managed ZIP updating an existing managed solution with the same unique name in the target**. The exact ZIP bytes and target solution metadata determine the policy. First managed installations and unmanaged imports receive 60 minutes.
- Both asynchronous monitoring and the synchronous import fallback use the selected limit. Async polling starts after accepted submission; status requests and delays are capped by the remaining budget.
- Import timeout returns the job IDs and selected policy, stops later queue items, and stops the agent before dependency repair/retry. A local timeout does not cancel a Microsoft job; inspect the target before retrying.
- The separate Microsoft background installation wait remains **15 minutes**, normally checking every **10 seconds**. Import time does not consume that background wait.
- Packages, ordered sequential deployment, reused Dataverse sign-in, grouped History with individual solution details, ZIP integrity checks, three/four-part existing ZIP versions and the latest approval presentation are included from the current workspace.
- Added the [Word setup guide](../PowerApps-Helper-Setup-Guide.docx) and its [maintainable source](../setup-guide.md), covering desktop installation, the Helper solution, five flow connections, profile/permissions, central or target setup, packages and recovery.

The desktop currently uses **ImportSolutionAsync / ImportSolution**. It has no separate stage-and-apply-upgrade action. The three-hour policy increases the wait for existing managed-solution imports; it does not change import semantics or implement component-removal upgrades.

Desktop version and both lockfile root versions are **0.1.6**. The Helper Dataverse solution remains **1.1.3.1**. Dependencies, application identity, Dataverse schema, publisher prefixes and import action payload are retained.

## Setup and update

Wait for active deployments to finish and close Helper before updating. Keep a private app-data backup and the preceding installer. Install the new desktop and reopen it. Keep it running and connected throughout deployment; idle-sleep protection does not prevent forced sleep, shutdown, lid policies or network interruptions. Automatic queue resume and rollback are not implemented.

Basic deployment does not require the Helper solution. Outcome emails and approved repairs require a configured setup environment. Each organization supplies its own connections, profile, recipients and permissions. Follow the setup guide and inspect actual flow delivery before rollout.
